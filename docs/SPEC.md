# Proxyz 0.1 製品仕様

2026-10-15更新：利用者の指示で操作体系をCLI＋トレイへ変更した。現在の操作は [CLI.md](CLI.md) を優先する。以下のWPF画面・文字倍率・GUIキー操作は旧GUI仕様で、ソースと検証表は `archive/Proxyz.Wpf` に保存した。プロファイル・ルール・WinINet適用/復元・競合回避は維持する。WinHTTPは今回から読取り専用診断と明示URLへの通信テストに限り対象とし、設定管理・同期は行わない。

状態：第1段階の確定仕様。第2・3段階のソース実装を伴う。実機での受け入れは第4段階。

## 1. 目的と対象

「異なるネットワークへ移動するたび Windows のプロキシ設定を開く必要がある」を解消する。対象は Windows 10 / 11 の対話ログオン中ユーザー。製品名は Proxyz。日本語 UI を基本とし、開発言語は本実装では C#、GUI は WPF を採用する。

変更対象は現在のユーザーの標準 LAN / Internet 接続の WinINet 系設定のみ。他のプロキシ設定を勝手に同期しない。設定反映済みと通信成功は別に扱う。[S03](SOURCES.md#s03-wininet)

**初期実装から除外**：WinHTTP（ユーザー/マシン）、Windows サービス、VPN 接続個別のプロキシ、アプリ固有設定、任意コマンド、認証情報、通信中継、DNS/ルート/証明書/ファイアウォール変更、クラウド、速度測定、詳細通信ログ。以前の案で「詳細機能」とした WinHTTP は、安全な実機検証が必要な別機能として今回は含めない。UI に未完成の機能のボタンを出さない。

## 3. 設定プロファイル

`Profile` は ID、名前、メモ、`ProxySettings` を持つ。プロファイル名は1～80文字、重複不可。メモは1000文字以内。現在の Windows 設定を取り込める。

UI の基本方式は直接接続、自動検出、PAC、共通の手動サーバー。詳細方式は Direct フラグ、WPAD、PAC、手動を個別に保持し、組織が指定した組合せを壊さない。Direct フラグの組合せは Windows への指定であり、Proxyz が独自のフォールバックを実行するわけではない。

手動は `host:port` または `http=host:port;https=host:port` 等。詳細では `ftp` / `socks` の既存表現も許可するが、アプリ側のプロトコル対応は保証しない。ポート1～65535、IPv6 は `[address]:port`。認証情報入り endpoint は拒否する。PAC は認証情報を埋め込まない HTTP / HTTPS URL。PAC URL のクエリに組織トークンが含まれる可能性はあり、端末内データとして保護する。Proxyz 自身は取得・評価しない。

除外先は Windows の表現のまま保持する。通常画面では改行で編集し、ネイティブ設定へはセミコロン区切りに変換。`<local>` を別スイッチで表現する。ホストや URL をネットワークに送って入力検証しない。

読み取り・復元用記録は、無効な方式の残存文字列も保持する。新規入力の検証で許可しない古い表現があっても、復元記録からは元の値を試みられる。ただし現在設定を編集可能プロファイルへ保存する際は入力検証を通す。すべてのレガシー表現を新規編集できるとは約束しない。

## 4. 自動切替

判定の入力は `NetworkSnapshot`。Wi-Fi の SSID は32バイト以内の生バイト（16進表現）で比較する。表示名の文字コード推測を一致条件にしない。NLM の ID は OS の認識に依存し、恒久的な組織 ID ではない。[S04](SOURCES.md#s04-network)

ルールは「SSID」「Windows ネットワーク ID」「両方」のいずれか。接続種別を任意で加えられる。ルールの優先順位編集や任意の条件式は実装しない。対象ネットワークごとに一致する全ルールが同じプロファイルを指すときだけ単一結果にする。

| 条件 | 自動動作 |
|---|---|
| 自動切替無効 / 一時停止 | 変更しない |
| 起動時に未完了の適用記録 | 復元待ち。勝手に復元/再適用しない |
| Windows 設定が最後の自分の適用値と違う | 外部変更として保留 |
| ネットワーク情報が不確実 | 変更しない |
| 検知した VPN があり、VPN 時停止が有効 | 変更しない |
| 接続がない | 変更しない。切断だけでは Direct にしない |
| 全接続で同一のプロファイルに一意に一致 | 適用 |
| 同じ接続で異なるプロファイルに一致 | 曖昧なので変更しない |
| 複数接続が異なる結果 / 一致と未登録が混在 | 曖昧なので変更しない |
| 未登録の Wi-Fi で SSID 取得不可 | 変更しない（ID で明確に一致するルールは使える） |
| 未登録の仮想/その他の接続 | 安全側で変更しない |
| 完全に識別できた未登録接続 | 既定は維持。利用者が選んだ場合だけ Direct |
| 自動適用に失敗 | 同一接続での再試行を抑止。再開操作または確かな接続変化まで待つ |

NLM / WLAN / IP変更イベント、起動、スリープ復帰、セッション復帰で再判定する。イベントの連続は1.5秒のデバウンスでまとめる。定期的な外部接続、Wi-Fi スキャン、数秒ごとのネットワーク全取得はしない。取得に必要な位置情報の許可を回避しない。識別を有効にする前に説明する。[S05](SOURCES.md#s05-wifi)

## 5. 手動操作とライフサイクル

手動適用と復元は、現在値と変更先を表示した確認画面を必須とする。最初のフォーカスは取消。確認中に現在値が変わった場合は中止し、再確認する。

手動適用・復元・プロファイル/ルール編集は、自動切替を永続的に一時停止する。保存だけでは Windows 設定を変えない。「次の接続で解除」など暗黙の期限を設けず、利用者が再開する。設定変更中に背後で古いルールが適用されないよう、UI 操作は直列化する。

× はトレイへ隠す。メニューから明示終了。設定は終了後も OS に残ると表示する。ログイン時起動はユーザーが有効にした場合のみ HKCU Run に登録。Windows 起動前/サインアウト後の監視は行わない。

同じユーザーが複数起動しないよう、ユーザーデータフォルダーでファイルロックを取る。別ユーザーはそれぞれ独立。アクティベーションは同一セッションの通知であり、他ユーザー/別セッションを操作しない。

## 6. 適用・復元

適用前の状態を読み、管理制限を確認し、ジャーナルへ Before / Intended を永続化した後に WinINet API を呼ぶ。変更通知と読み戻しが一致して初めて「設定に適用」とする。通信の成功は表示しない。

失敗した場合は、自分の変更であると保守的に判断できる範囲で Before へ復元する。外部値が混ざった場合や管理制限がある場合は競合を避けて未完了記録を保持する。初回変更前と直前の2種類の戻し先を持つ。未完了記録がある場合は、その Before を優先して回復する。

WinINet の変更とディスク書込みを一つの OS トランザクションにはできない。直前比較・意図記録・読み戻しで被害を抑えるが、電源断と第三者の同時変更を完全には排除できない。

## 7. UI とアクセシビリティ

ホーム / プロファイル / 自動切替ルール / 設定の4画面。最初に現在のネットワーク、現在の設定、切替状態、理由、主操作を見せる。設定や停止理由を色やアイコンだけで表さない。画面幅が足りない場合は折返し/スクロールし、トレイが使えなくても全操作を提供する。

標準 WPF コントロール、UI Automation 名/関連ラベル、予測可能なタブ順序、アクセスキー、視認できるフォーカス、エラー/状態の live region、OS のコントラスト色、DPI と文字拡大を実装対象にする。具体的な合否は [ACCESSIBILITY.md](ACCESSIBILITY.md) に定義する。
