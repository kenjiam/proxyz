## レベル1：純粋ロジック/障害注入

```powershell
dotnet run --project .\tests\Proxyz.Core.Tests -c Release
```

OS のネイティブアダプターを参照せず、FakeProxy / MemoryStore でテストする。保存テストだけは一時ディレクトリを使う。プロキシ/PAC/SSIDをネットワークへ送信しない。

- 設定モード・比較・不正 endpoint / PAC / SSID / プロファイル名 / schema。
- 同名SSIDとID、AND、無接続、判定不能、未登録、VPN、競合、一致先重複。
- 手動/自動/停止/再開、適用前のジャーナル、読み戻し、バックアップ、初回/直前復元。
- OS/通知/永続化/復元の失敗、部分変更、外部書込み、確認中の変更、保護されたプロファイル削除。
- 再起動時の Pending、同じネットワークでの失敗ラッチ、操作の直列化、設定の複製。
- 原子的ファイル保存、.bak、壊れたデータ保持、ログの秘匿値除外。

標準出力に各 `PASS` / `FAIL` と件数、終了コード0/1を出す。通常の xUnit / MSTest アダプターではないため `dotnet test` は代替にならない。

## レベル2：ABI / 読み取りだけ

```powershell
dotnet run --project .\tests\Proxyz.Windows.Tests -c Release
# 設定やNLMを読み取るオプション。実行前に読み取り内容を説明する。
dotnet run --project .\tests\Proxyz.Windows.Tests -c Release -- --read-os
```

既定：Marshal.SizeOf / OffsetOf で WinINet union / list と WLAN struct の配置を確認。`--read-os` は current-user proxy / policy / NLM を読む。WLAN 識別は consent=false、設定書込みはテスト実行形式に存在しない。

x64 を必須とする。x86 / ARM64 配布が必要になった場合には、そのアーキテクチャで実行してから対応を主張する。

## レベル4：実機・明示許可後

以下は**既定テストで自動実行しない**。設定を変更するものは内容/戻し先を利用者へ説明し、同意を得る。Windows 10 22H2 x64 と Windows 11 x64 の環境を明記する。

| ID | シナリオ | 合格条件 |
|---|---|---|
| W01 | 起動/現在設定保存 | 最初の起動だけで OS を変更しない。現在値を取り込める |
| W02 | Direct ↔ Manual | API読戻しと設定UIが一致し、戻せる |
| W03 | PAC / WPAD / 組合せ | 有効フラグと文字列が保たれ、勝手なDirect fallbackなし |
| W04 | 非有効の残存値 | 方式を変えても復元が元の値を保つ |
| W05 | 手動一時停止 | 接続先が変わっても、再開まで自動適用しない |
| W06 | Wi-Fi識別の許可 / 拒否 | 拒否を説明。SSIDを推測しない。手動/IDルールを使える |
| W07 | 同SSID別ネットワークID | 設定したAND条件の拠点以外へ勝手に適用しない |
| W08 | 有線 + Wi-Fi / 仮想NIC | 意図しない往復切替なし。曖昧状態の理由が分かる |
| W09 | VPN接続・切断 | 検知したVPNで既定保留。VPN専用設定を変更しない |
| W10 | 外部設定書換え | 上書き合戦なし。確認付き再開でのみ再取得/適用 |
| W11 | 管理ポリシー | 変更制限を尊重。状態が読めないときにも安全側 |
| W12 | 失敗・強制終了・回復 | Pendingを検出し勝手な変更をせず、確認して回復できる |
| W13 | スリープ/ロック/復帰 | 起動時と同じ判定。瞬断で連続書込みしない |
| W14 | ログイン起動・トレイ・終了 | オプトイン登録/解除、×で常駐、明示終了、設定残存の表示 |
| W15 | Edge等への反映 | 実際に使うアプリで確認。反映外アプリを全対応と表示しない |

自動化の例外を実 OS 上で故意に起こすのは危険なため、永続化失敗/第三者レースの多くはまず偽アダプターで検証する。実機で同等の故障を再現する必要がある場合も、使い捨てVM等で同意後に行う。
